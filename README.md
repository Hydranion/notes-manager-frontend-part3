# Notes Manager — клієнтська частина (практика, частина 3)

Окремий клієнтський застосунок для теми 6 «Менеджер нотаток із категоріями та пошуком». Він використовує REST API серверної частини, підготовленої для частини 2. Папка та звіт частини 3 відокремлені від матеріалів частини 2.

## Технології

- Vue 3 та Vue Router для компонентного інтерфейсу й навігації;
- SCSS для змінних, міксинів, стилів компонентів і адаптивного макета;
- Fetch API через клієнт `ApiClient` для HTTP-запитів;
- Vue `provide` / `inject` для Dependency Injection сервісів;
- `localStorage` для збереження параметрів пошуку та фільтрів у браузері.

## Запуск обох частин

Потрібен Node.js 20.19+ або 22.12+. Сервер і клієнт є окремими проєктами та запускаються у двох терміналах.

### 1. Серверна частина (практика, частина 2)

Клонуйте окремий [репозиторій сервера](https://github.com/Hydranion/notes-manager-backend) і в його корені виконайте:

```powershell
npm install
Copy-Item .env.example .env
npm run migrate
npm start
```

Типова адреса API — `http://localhost:3000/api`; Swagger UI — `http://localhost:3000/api-docs`. У файлі `.env` сервера значення `CORS_ORIGIN` має бути `http://localhost:5173` (це значення вже задане у `.env.example` сервера).

### 2. Клієнтська частина (практика, частина 3)

У корені цього проєкту виконайте:

```powershell
npm install
npm run dev
```

Відкрийте `http://localhost:5173`. Якщо API працює за іншою адресою, скопіюйте `.env.example` у `.env`, змініть `VITE_API_URL` і перезапустіть Vite. Якщо Vite вибрав інший порт, оновіть `CORS_ORIGIN` у `.env` сервера відповідно до адреси клієнта.

Для production-збірки виконайте `npm run build`; готові файли з'являться в `dist/`.

## Основні можливості

- створення, перегляд, редагування та видалення нотаток;
- фільтрація за категоріями й тегами, пошук за текстом;
- створення, перейменування та видалення категорій;
- створення й видалення тегів;
- стани завантаження, порожнього списку та помилки API;
- адаптивний інтерфейс для вузьких екранів.

## Архітектура

`src/components/` містить повторно використовувані компоненти інтерфейсу, `src/views/` — сторінки маршрутизатора, `src/services/` — HTTP-клієнт і сервіси даних, `src/composables/` — DI та браузерні налаштування. Для кожного інтерфейсного компонента є окремий SCSS partial у `src/styles/components/`; стилі сторінок винесені в `src/styles/views/`, спільні елементи — у `_shared.scss`. `main.scss` об’єднує модулі, змінні та міксини. Точка входу створює сервіси та передає їх через `app.provide`; сторінки отримують їх через `inject`.

API надає сервер частини 2. Код сервера, звіт ч. 2 та його GitHub-репозиторій цей окремий клієнтський проєкт не змінює.
